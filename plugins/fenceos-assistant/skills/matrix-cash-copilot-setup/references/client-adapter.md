# Client capabilities: ChatGPT, Claude and Codex

Use this same workflow in a supported ChatGPT desktop Work, Claude Cowork/Code or Codex session. Plugin loading and interactive browser access are separate capabilities; a CLI registration does not establish ordinary ChatGPT chat access or transfer a signed-in browser session. Before promising execution, inspect actual interactive browser, file-reading/creation and email tools. On desktop, use the built-in browser by default. In another supported client, use its actually available authorized browser and record the route. If mcp__cua_repl is available, initialize exactly as its current tool instructions require and follow its returned API documentation. Never invent methods or use shell-driven browser automation. Missing control means preparation work until a supported route exists, not pretending web search can click.

Use [Browser connection](chrome-connection.md) only when access or fallback is needed. Chrome is conditional on a concrete allowed blocker or explicit user preference. One operator handles writes; independent read-only extraction is permissible only when authorized and useful. Private sign-in, sensitive consent and tool-required handoffs stay with the owner.

Sign-in belongs to the browser session that completes it. A phone browser or separate cloud browser does not authenticate the Mac's built-in browser. Use a secure sign-in handoff only when the current tools actually offer one for the intended session; never invent a prompt, QR link or session transfer. If changing to a supported cloud workflow, name the separate session and recheck the business there. Do not copy credentials or cookies between clients. Without a supported handoff, preserve the checkpoint and wait for the owner to sign in to the required browser.

Recommend GPT-6.1 Sol with High reasoning when actually offered for the full setup; otherwise choose the user's available capable model and retain validation. Use a stronger offered reasoning model for a bounded unresolved reconciliation, and cheaper models only for easy read-only extraction that will be checked. Respect explicit user choice. Keep one suitable model through a typical session, avoid switching distractions, and do not claim a change without control confirmation. High reasoning grants no extra permissions. Use current picker/tool controls rather than a memorized menu.

Use supported plugins for scoped email and local file tools for analysis. Check connected identity; account availability does not establish scope. If file creation is absent, give a copyable private checkpoint and state that it is not saved. Record actual client/model, browser route and capability gaps in test receipts. These recommendations are not measured accuracy guarantees.
